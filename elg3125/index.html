None of this is handed in and none of it is worth marks. Three things confirm it. The marking scheme already adds to 100 percent without them. Every set has its full solution posted beside it, which no graded work would. No due date appears anywhere on the course page.

The marks come from the Friday tutorial quiz. Eleven quizzes run at the start of tutorial, the best ten count, and together they are worth 10 percent. Working the matching assignment set beforehand is the preparation for that quiz.

What the search turned up

uOttawa Omni returns six results for the author and title. One is the book that matters: Signals & systems, Oppenheim, Willsky and Nawab, 1997, on Reserve at Morisset plus other locations. A 1983 first edition with Young as third author is in the General Collection at QA 402 .O63 1983, and its problem numbering does not match what the assignments ask for.

There is no electronic copy through the library. The only results offering online access are a 1985 journal review of the book and two unrelated book chapters. A 2015 printing shows as not available locally.

The route taken was a Reserve loan, with the problem pages for chapters 1 to 3 photographed first because those carry the midterm.

Build a problem index from the textbook
A script scanned the book for problem markers and recorded which page each numbered problem starts on, writing a small index file. Nothing from the book was read into a conversation during that step, so the index cost almost nothing to build and makes every later lookup a single page.
Done
How the index is built

The book is never read into a conversation. A script walks the pages and writes a small table; the conversation only ever sees the handful of pages a given assignment needs.

  1. Extract text page by page with PyMuPDF. If the source is photographs, run optical character recognition first with ocrmypdf, which adds a searchable text layer without changing how the pages look.
  2. Match problem markers at the start of a line, in the shape ^(\d+)\.(\d+)\., and record chapter, problem and page.
  3. Write Working files/problem-index.json as a map from problem number to page.
  4. Check the index against the five problem numbers already known from Assignment 1, which are on Oppenheim pages 59 to 61. If those come out right, the rest are trustworthy.

A whole textbook is far too large to read directly. The index makes the cost independent of the size of the book.

Page format, and how problems get marked

Each problem appears twice, as typed text and as a picture, because neither alone is enough. Typed text renders the mathematics properly, can be searched, and costs almost nothing to revisit. Many problems refer to a figure, such as Figure P1.21 in the first assignment, and a figure has to be an image.

  • Typed statement. The problem written out in the page, with the mathematics set properly. This is what reads first.
  • The figure where one is referenced, cropped from the page and placed beside the statement.
  • The full source page inside a closed toggle, with the assigned parts ringed, for checking against the original.

Drawing the rings. PyMuPDF searches a page for the problem label, for example 1.21, which returns the rectangle holding it. Widening that rectangle to the column and adding page.add_rect_annot in the accent colour draws a ring around the problem. Rendering afterwards bakes the ring into the image. Only the assigned parts are ringed: for Assignment 1 that means 1.21 (c)(d)(e), 1.22 (b)(d)(e), 1.23 (b), 1.24 (c) and 1.25 (a)(c)(e), leaving the unassigned parts plain.

The marking was built and checked on the Assignment 1 scan first, because those three pages were downloaded while the rest of the book was still being sourced.

Repository shape, shared design system, favicon

A new repository was built, leaving the philosophy one alone. The repository phi-reading-hub already serves published pages at a URL that has been shared, its week 1 guide is a 285 KB page carrying saved highlights, and its browser storage keys are tied to that origin. Renaming it breaks the published address and every stored highlight. A new umbrella repository costs nothing, and philosophy is reached from it by a link.

The shape of the new repository, course-hub:

  • index.html, the front page, one card per course
  • shared/hub.css, the design system every hub imports: colour tokens for light and dark, type scale, the card, the table, the task list, the footer
  • elg3125/, ceg3155/, gng2101/, each its own hub page
  • The philosophy card links out to myermcat.github.io/phi-reading-hub
  • .nojekyll, so GitHub Pages serves the files untouched

Extracting the shared stylesheet is the part that stops work being redone. This page carried its own copy of the tokens and the components until it moved here, and the philosophy hub in its separate repository still carries one. A single file, imported by every page here, means a change to the card or the dark palette happens once. Each hub keeps only its own accent colour.

Everything on the repository that goes stale, to change in the same pass: the repository description, the topics and tags, the README, the Pages source branch and folder, the social preview image, the About section website field, and any link in the course READMEs pointing at the old address.

Favicon. One mark for the umbrella, then a per-course variant in that course's accent colour, so tabs stay tellable apart. Drawn as inline SVG in a data URI, which needs no file and no network request, the way this page already does it. The philosophy lightbulb does not carry over to four courses and gets replaced.

Decide how the hub skill is split
The original skill was written for reading philosophy. Separating what every hub shares from what belongs to one kind of course kept the useful parts, and an engineering course is no longer pushed through a method built for narrating arguments.
Done
The recommendation and the reasoning

Three pieces. The shared parts were pulled out into their own reference, and both course skills point at it.

  1. A shared reference holding what travels: the design system, the prose rules and the linter, the interaction rules, browser storage and its export, the accessibility and dark mode requirements, the folder convention, and the publishing steps.
  2. course-readings, kept as it is. Its heart is narrating an argument for someone who will not read the source, and that method suits philosophy and suits nothing in this course. It keeps the guide specification, the explanation standard and the optical character recognition pipeline for scans.
  3. A new problem-set skill for the engineering courses: the assignment table, the problem index, marking up source pages, worked solutions, and preparing for a weekly quiz.

Why one general skill was rejected. The explanation standard in the philosophy skill exists to stop summaries that teach nothing about an argument. A problem set has no argument to narrate, and folding the two together would either bury that standard or apply it where it does not belong. The parts genuinely shared are the interface and the prose, which is what the shared reference holds.
