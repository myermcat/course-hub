1. The gist

A keyboard reports every key press and every key release as a short burst of bits on two wires. You build the circuit that catches those bits, assembles them into a byte, and puts that byte on two hexadecimal digits.

The Nexys has no keyboard socket of the old kind. A USB keyboard plugs into connector J5, and a small processor already on the board turns it into the two wire protocol the FPGA expects, so what arrives at your pins is a clock and a data line.

The demonstration asks for the last byte of the break code, meaning the byte that goes out when a key is let go.

2. The handout teaches one thing and marks another

Costs the whole laboratory

Sections 3 to 6 are fifteen pages on asynchronous sequential design: fundamental mode, flow tables, races, hazards, the material of Assignment 4. Then section 7 says in bold that the solution handed in must be synchronous.

The asynchronous version is worth 10 bonus marks and nothing more. Build the synchronous circuit first, complete, working and demonstrated. Only then consider section 7.4.

3. What the keyboard actually sends

Eleven bits per key event, least significant bit first.

  1. One start bit
  2. Eight data bits, the scan code
  3. One odd parity bit, so the nine bits together hold an odd number of ones
  4. One stop bit

Pressing a sends the code 1C, which travels as 0 00011100 0. Between frames the line stays idle for as long as nobody types.

Press and release send different things. A press sends a make code. A release sends a break code, which for most keys is F0 followed by that same make code. Holding a key down repeats the make code until it is released.

So a single tap on one key puts three bytes on the wire. Your circuit shows whichever byte arrived most recently, which after a release is the make code again, and that is what the demonstration wants.

The code chart for every key is figure 14, the last page of the handout.

4. The six blocks

BlockWhat it does
FSM controllerDecides everything and drives the other five
4-bit counterCounts how many bits have come in, so the machine knows when a frame is finished
Digital filterCleans the keyboard clock before anything samples on it
D flip-flopHolds the start bit at the end of a frame
Shift registerCollects the scan code off the data line, one bit per filtered clock edge
BCD decoderTurns the assembled byte into the two hexadecimal digits

The lines between them in figure 12 are Set Compteur and Enable going out to the counter, Compte[3..0] coming back, Décale going to the shift register, and Scan Code[7..0] going to the decoders.

The shift register and the flip-flop take their clock from the filter. clk_filtrée is what moves data in; the 100 MHz global clock runs the filter itself and the rest of the design.

5. The filter, and the error Vivado will give you

The keyboard clock is slow next to the FPGA, and a signal coming down a cable reflects off the far end, which can put extra edges on it. One false edge shifts one false bit and the whole byte is wrong.

The filter refuses to believe an edge until the line has held still for eight global clock periods. The raw keyboard clock goes into an 8-bit shift register clocked at 100 MHz. All eight bits feed two AND gates, one asking whether they are all ones and one whether they are all zeros, and those two set and reset a latch. The latch output is clk_filtrée, and it changes only after 80 ns of agreement.

That latch is a loop of gates feeding each other, so Vivado stops at synthesis and reports a combinational loop. It is deliberate, and the waiver goes in the constraints file:

set_property ALLOW_COMBINATORIAL_LOOPS TRUE on the net clk_filtree.

The handout notes the older 50 MHz board gave a 160 ns window and says the filter can be taken to 16 stages to get that back, which is a sentence worth quoting in the report if the circuit misreads bits.

Part XC7A100T-1CSG324C, top module controleurClavier, everything LVCMOS33. Start from Nexys-A7-100T-Master.xdc and uncomment only the lines you use.

The reset pin is active low and is inverted once, at the top level. Every block below it then sees an ordinary reset.

No MMCM and no PLL. Anything slower than the system clock comes from a counter producing an enable. The clock itself is constrained with create_clock -period 10.00, and the file also needs set_property CFGBVS VCCO and set_property CONFIG_VOLTAGE 3.3.

7. The rules that cost marks

Section 9
  • VHDL only. Verilog is refused.
  • Structural style. Behavioral modeling is not accepted, with one exception made for a clock divider.
  • The top level entity is structural VHDL. Vivado has no graphical block entry, so the wiring is written out by hand, and every atomic module is yours.
  • No cores from the vendor catalogue or the internet. Cores given out by the course are allowed, and have to be referenced.
  • Mealy or Moore is your choice.
  • Synchronous and globally resettable. Clock and reset reach every functional block.
  • Demonstrate it to the professor before the report is due, with a USB keyboard in J5 and the byte on the two outputs.

8. How to approach it

Do the pre-lab before the session and do it together. The five steps are the same ones Laboratory 3 used, and the counter plus the filter plus the shift register are all small once the state machine is settled. Getting the machine wrong costs the session.

Agree the signal list before splitting up. Name and width of every wire crossing from the controller into the other blocks, written down. One person then takes the filter, the counter and the shift register, the other the controller and the decoders.

Simulate the filter on its own first. Feed it a clean clock, then a clock with a spike on it, and watch clk_filtrée ignore the spike. If that is wrong nothing downstream can be debugged.

Then the whole thing in simulation, with a testbench that drives eleven bits for 1C, before the board is touched.

9. Bonus

Ten marks for building every block except the digital filter asynchronously: controller, counter, flip-flop, shift register, decoder. No global clock, and fundamental mode has to hold throughout. The controller follows chapter 9 of the textbook and section 3 of the handout. The report explains what changed, and the new design is demonstrated too.

10. What goes in the report

  • Timing simulations, with an explanation, for every source file
  • Every file described and commented
  • A flowchart and a block diagram of the solution
  • The full FSM diagrams, tables and circuit implementations
  • The solution in your own words
  • The obstacles and how you got past them
  • All the .vhd files, the structural top level included
  • An archive holding the VHDL and the Vivado project with its constraints file

The obstacles section has an obvious occupant. The combinational loop error in section 5 is a problem the handout plants on purpose, and writing up how it was found and waived is free marks.
