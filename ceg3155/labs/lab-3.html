Laboratory 3

A traffic light controller for an intersection, designed by the finite state machine method. Due Wednesday 11 November 2026 at midnight on Brightspace.

Laboratory 3 handout Laboratory 2 quick guide

Pre-lab

Shown to the TA at the start

The first six FSM steps for this controller, worked on paper and explained to the teaching assistant.

  1. State diagram. A bubble for each situation the intersection can be in, arrows for what moves it between them, each arrow labelled with the condition that causes the move.
  2. State table. The same thing as a table, one row per state, with the next state and the outputs.
  3. State minimisation. Merge any two states that behave identically, meaning the same outputs and the same next state for every input. Section 3.4 works an example.
  4. State assignment. Choose the bit pattern for each state. Section 3.5 covers why the choice changes how much logic comes out.
  5. Transition table. The state table with those bit patterns in place of the letters.
  6. Then the design equations and the circuit, which come after the session.

The handout never says how many states the answer has. Working that out is the exercise.

1. The gist

Two roads cross. The main street has priority and keeps the green by default. The side street gets a green only when a car is waiting on it, which a sensor reports.

  • Main green with side red is the resting state.
  • Main holds green for MSC, set on the switches. After that, if a car is on the side street, main goes yellow for the fixed MT, then red.
  • Side goes green for SSC, also on the switches, then yellow on its own for the fixed SST, cars or not, then red. Main goes green again.
  • If no car is waiting when MSC runs out, main holds green until one arrives, and then changes with no further wait.

The last two rules are one condition, and the handout spells them as two sentences. Waiting past MSC for a car and leaving the moment the car comes are the same transition. MSC is a minimum green for the main street, counted from the moment the light turns green, so a car arriving early waits and a car arriving late costs nothing.

One typo worth knowing. Section 4.1 reads "If after MST, there are no cars on the SS". MST is the main street yellow timer, which has nothing to do with that sentence. It means MSC, and reading it literally is what makes the two sentences look contradictory.

2. The names

MS, SS
main street, side street
MSTL, SSTL
the two light outputs, three bits each, one hot over red, yellow and green
SSCS
side street car sensor, 1 while a car waits
MSC
how long main stays green, set on the switches
SSC
how long side stays green, set on the switches
MT
how long main stays yellow, fixed in the design
SST
how long side stays yellow, fixed in the design
ISP
in system programmable, meaning changed from the board while it runs

The two greens are on switches and the two yellows are written into the design. That split is the only difference between what the handout calls a counter and what it calls a timer.

Figure 9 is captioned "A potential system diagram" and section 4.2 calls it "a possible solution". None of it binds you. Section 6 holds the rules that do. Following the figure is the low risk choice, since the teaching assistant will recognise it.

The FSM never sees a count. It drives one signal to start a block and reads one bit back saying the block finished. If the count reached the state machine, a programmable period would need a different machine for every switch setting, which is the reason the counting lives outside.

One hot on the lights is bit 2 red, bit 1 yellow, bit 0 green. Section 5.4 lists every bit.

The yellow bit drives the blue channel of the RGB LED, so the yellow phase lights the blue diode unless red and green are mixed in the top level.

SSC_MAX[3] is on SW8 at pin T8, which sits on a 1.8 V bank while everything else is LVCMOS33. It may read unreliably. Move it to another switch or set that one port to LVCMOS18.

The LEDs are positive logic and the display is active low on both the segment bus and the anode bus.

5. What the reset does

RESETBAR is the dedicated CPU RESETN button, so it needs no debouncer. Section 4.2.2 says it reaches the other blocks as well as the FSM and "will cause the other blocks to enter their reset condition", which is how the counters and the timer start from a known value without the state machine driving anything.

6. The rules that cost marks

Section 6
  • VHDL only, structural only, RTL mandatory. Behavioural is accepted for the clock divider and nothing else.
  • Every atomic module is the group's own, the D flip flop, the one bit comparator and so on.
  • No IP cores of any kind. Course provided cores are allowed and have to be cited.
  • Graphical design for the top level entity.
  • Synchronous and globally resettable, so clock and reset reach every block.
  • Simulate every design against the theoretical result.

7. How to approach it

The teaching assistant's advice, given on 4 November. Use one counting block for all four periods and pick between them with the select, the same way one comparator already serves two counters. Make both yellows the same length, since there is no reason for them to differ, which removes one period entirely. The greens can still differ.

Write each input as its own column in the state table. A single condition column is quicker to write and cannot be fed into a K-map, which is what the minimisation and the design equations need. Fewer inputs means narrower maps, which is the other reason to share the counting block.

Settle the machine that runs Vivado before the session. Synthesis and programming need Windows or Linux on x86, and an install started on the evening costs most of the evening.

Section 5.5 names the scenarios to simulate. Main green with no car, a car arriving before the programmable green time, a car arriving after it, the automatic side street yield, and debouncer integrity.

8. Bonus

Five marks for showing the current count on the seven segment display in decimal. It must not go past the programmable MSC maximum, and must hold there until a car arrives. All eight digits share one cathode bus, so it needs the multiplexed display controller as well as the decoder, and it has to be demonstrated to the teaching assistant.
